Antes de grabar, verifica. Ninguna de las verificaciones que han valido en este proyecto vino del log de compilación: vinieron de mirar el artefacto. El SHA-256 es el primer vistazo, y con las recompilaciones del mismo día es la única forma de saber qué imagen probaste.

Verificar la descarga

Linux, WSL o macOS

sha256sum willylinux-v2.8-kde-amd64.iso
# 825ec3bba88b4610244f1de889951c13e343b53f014d0bbb223a6d55874041bb  willylinux-v2.8-kde-amd64.iso

sha256sum -c willylinux-v2.8-kde-amd64.iso.sha256      # si bajaste también el .sha256

Windows

Get-FileHash -Algorithm SHA256 .\willylinux-v2.8-kde-amd64.iso
# o, con el fichero .sha256 al lado:
certutil -hashfile .\willylinux-v2.8-kde-amd64.iso SHA256

Si el hash no coincide, no la grabes: vuelve a descargar. Un USB con una ISO truncada arranca y falla de formas que parecen defectos del sistema.

Verificar lo que hay dentro (opcional, para el que audita)

mkdir -p /mnt/willy && sudo mount -o loop,ro willylinux-v2.8-kde-amd64.iso /mnt/willy
ls /mnt/willy/live/            # filesystem.packages  filesystem.squashfs  initrd.img  vmlinuz
grep -c . /mnt/willy/live/filesystem.packages          # 1712 paquetes en esta edición

mkdir -p /tmp/wsq && sudo mount -o loop,ro /mnt/willy/live/filesystem.squashfs /tmp/wsq
awk -F: '$3==1000 {print $1, substr($2,1,7)"…"}' /tmp/wsq/etc/shadow   # tiene que salir un hash
test -x /tmp/wsq/usr/bin/cfdisk && echo "cfdisk está"                  # faltaba en la del 20-10

El guion src/pruebas/verificar-2.8.sh hace todo eso y más (sintaxis de los 22 guiones propios, binarios de GRUB, perfiles ALSA, ping_group_range) y saca OK o MAL por línea.

Grabar el USB

Windows — Rufus

  1. Dispositivo

    El USB. Se pierde todo lo que hubiera dentro.

  2. Imagen de arranque

    La ISO de Willy Linux recién verificada.

  3. Modo de particionado: DD

    Rufus pregunta; elige «Modo imagen DD». El modo ISOHybrid también vale, pero DD es el que está probado en todos los equipos.

  4. Espera a «LISTO»

    Y expulsa el USB antes de apagar.

Linux o macOS — dd

sudo umount /dev/sdX*                  # sin el * final si no está montado
sudo dd if=willylinux-v2.8-kde-amd64.iso of=/dev/sdX bs=4M status=progress oflag=sync
sync

Escribe en /dev/sdX (el disco entero), nunca en /dev/sdX1 (una partición). Y copiar la ISO con el explorador de archivos no deja un disco arrancable: es el fallo de arranque más común que reportan.

Arrancar y probar

Entra al firmware con F12, F8, Esc, F2 o Del y elige el USB en el menú de arranque temporal. Desactiva Secure Boot o pon «Other OS». Si tu equipo muestra las dos entradas del USB, usa la UEFI: arranca más rápido y el instalador puede registrar GRUB en el firmware. Sin apagar Secure Boot la entrada UEFI puede no aparecer o reventar con Security Violation: el BOOTX64.EFI de la ISO no va firmado.

En la live: usuario live, contraseña willy. sudo no pide contraseña mientras se arranca desde USB. El asistente de bienvenida se abre solo; si lo cierras, vuelve con willy-bienvenida o con el icono del lobito.

En las ISO quemadas antes del 2026-11-07 (incluida la 2.8 del 2026-10-20) la cuenta live no traía hash y, si la pantalla se bloqueaba, willy no la abría. Arreglo a mano nada más arrancar: echo willy:willy | sudo chpasswd. La release actual ya lleva la contraseña escrita en la imagen. Detalle en solución de problemas.

Instalar en el disco

Asistente → 11 · Instalar en el disco, o willy-instalar en un terminal. Pide el disco, exige escribir BORRAR, avisa si hay NTFS o BitLocker, y entonces particiona y copia.

OrdenQué haceSi algo falta
1preflight: grub-install, grub-bios-setup, efibootmgr y medio live realaborta sin borrar nada
2–4elige disco, escribe BORRAR, avisa de Secure Boot / BitLockersale sin tocar el disco
5esquema: GPT+ESP (UEFI) o msdos (BIOS), raíz ext4, swap si hay < 8 GB de RAMtambién hay rama manual con cfdisk
6–7formatea, rsync --one-file-system, fstab por UUID, purga live y regenera initramfscorta si la raíz sale sin UUID
8–9crea tu usuario con tu contraseña, quita el autologin de SDDM, grub-install + grub-mkconfig con os-proberWindows aparece en el menú si está en el equipo
10apaga, quita el USB, arranca del disco—

Nunca formatea la partición EFI de Windows: usa la ESP que ya existe y solo escribe ahí su entrada. Para quitar Willy Linux: efibootmgr -b <número> -B y formatear sus particiones; el arranque de Windows sigue intacto.

Ninguna ISO compilada antes del 2026-10-14 instala a disco: le faltaban grub-install y grub-bios-setup, copiaba el sistema y dejaba el disco sin arrancar. Desde la 2.5 del 14-10 el instalador comprueba esas herramientas antes de borrar nada.

Los ficheros de 1,8 GB no viven en Git (GitHub rechaza lo de más de 100 MB en el árbol): las ISO se publican como assets de las Releases, que admiten hasta 2 GB por fichero, y se conservan en disco con su .sha256. Ninguna imagen anterior se borra: se renombra a .bak-día.hora.
